# Illustration System

## Purpose

Illustration is part of Evelyn's HTML visual language. It should make presentation pages feel recognizably personal without turning work reports into cartoon pages.

The key rule is:

**Characters participate in the composition. They are not detached decoration.**

## Canonical main character

Default role:
**primary layout character**

Visual identity:
- young feminine line-art character
- short-to-medium curly blonde bob
- recognizable curl volume around the face
- simple, cute face
- expressive eyes, but not giant glossy Powerpuff-style eyes
- clean hand-drawn / sketch-like outline
- low-detail rendering
- minimal blush or soft pastel accents only
- no realistic 3D rendering
- no heavy painted shading

Canonical outfit:
- coordinated fitted short-sleeve blouse / top, tucked in
- pleated skirt
- elegant high heels
- light line-art treatment on all clothing
- avoid heavy solid black fills
- avoid oversized bows, chunky boots, or toy-like footwear

Overall character feeling:
**cute / smart / feminine / light / editorial / presentation-friendly**

## Supporting dog

Default role:
**secondary emotional / compositional anchor**

Visual identity:
- small fluffy cream/tan dog
- cute, gentle face
- may wear seasonal accessories when context supports it
- slightly more detailed than the main girl is acceptable, but should still harmonize with the line-art world

Use the dog to:
- anchor the base of a headline composition
- close awkward negative space
- support a warm, playful, or seasonal moment
- soften a conclusion or transition slide

Do not use the dog as the primary information carrier.

## Composition behavior

Preferred character behaviors:
- lean on a word or letter
- touch a keyword
- point to a metric or chart
- stand between two information blocks
- sit / stand on a baseline
- follow a process path
- visually react to a conclusion
- help direct the eye toward the next information step

Characters should overlap or physically relate to typography / diagrams when it improves the composition.

Avoid:
- separate illustration cards unless the content genuinely needs one
- bottom-right mascot placement with no narrative function
- full-height character that competes with the headline
- multiple major characters on one slide
- character poses that feel random or unrelated to the slide message

## Illustration density

Default:
- 1 main character maximum per slide
- 0–1 supporting dog / secondary character
- 0–3 small doodle accents

Dense data slides may use:
- no main character, or
- only a small partial character / pointer gesture

Simple title, transition, and conclusion slides may use a larger character presence.

## Doodle accents

Preferred motifs:
- tiny 4-point spark
- small heart
- short curved underline
- loose loop / path line
- hand-drawn arrow
- tiny dots / marks

Use these sparingly.

They should feel like light handwritten annotations, not a sticker pack.

## Presentation-specific rule

For PPT-style HTML:
- keep the slide at 16:9 / 1920×1080
- use character + typography as one visual system
- large type can act as a physical object for the character
- the character may overlap the title if readability remains strong
- prioritize compositional integration over ornamental placement

## Canonical cover pattern

A preferred cover pattern may look like:

- small context label in the top-left
- page / section number in the top-right
- oversized stacked headline
- main curly-haired line-art girl leaning on or gesturing toward the headline
- supporting dog near the bottom baseline
- one short supporting sentence
- 1–2 tiny doodle accents

Do not copy the same pose or layout every time; preserve the interaction principle.

## Do / Don't

Do:
- keep outlines light and clean
- keep clothing and shoes mostly outline-based
- coordinate character palette with blush / mauve / periwinkle
- let characters guide reading order
- reduce character scale when the slide is information-heavy

Don't:
- use heavy black skirt / boot fills
- use bow-covered shoes
- use fully rendered 3D mascot styling
- use huge glossy cartoon eyes
- separate the character into a decorative right-side panel by default
- place the character in a corner simply because there is empty space
